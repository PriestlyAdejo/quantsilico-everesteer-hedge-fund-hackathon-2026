## Before the event exists

It is normal for Event Control to show **NOT CONNECTED**, for leaderboard values
to be blank and for event capabilities to be unknown.

Do not populate those fields manually.

Use synthetic rehearsal to prove that the local machinery works without
pretending that a live event exists.

<Command>
.\.venv\Scripts\qseh.exe doctor
</Command>

<Command>
.\.venv\Scripts\qseh.exe rehearsal
</Command>

## Once Everesteer access is available

Start by inspecting the platform rather than training immediately.

<Command>
.\.venv\Scripts\qseh.exe event inspect
</Command>

Then capture the event state that subsequent actions will be tied to.

<Command>
.\.venv\Scripts\qseh.exe event snapshot
</Command>

The event/API and organiser instructions are authoritative for event mechanics.
Do not make an old README override the live event.

## Submission mode

The project has three submission states.

<MetricDefinition name="DISABLED">
External uploads cannot be performed.
</MetricDefinition>

<MetricDefinition name="DRY_RUN">
The submission pipeline can validate, package and record evidence without
uploading predictions to Everesteer. This is the safe default.
</MetricDefinition>

<MetricDefinition name="ARMED">
Real Everesteer uploads are permitted after explicit human action and still
remain subject to event, lane, quota, ID and artefact checks.
</MetricDefinition>

<Callout tone="warning">
Autopilot must never arm submissions by itself.
</Callout>

## Where to look

Use **Overview** to understand the current operating stage.

Use **Event Control** to verify platform state.

Use **Data Lab** before trusting a newly downloaded split.

Use **Experiments**, **Validation** and **Ensembles** while researching.

Use **Round Room**, **Submission** and **Leaderboard** during live rounds.

Use **Compute & Jobs** when you need to know whether an experiment will finish
in useful time.
